# 找房进度与策略映射

策略引擎只读取当前登录用户的房源，并以每套房源的**当前状态**计算摘要。操作日志用于审计，不参与恢复历史 Viewing。用户把状态退回较早阶段后，摘要和策略会一起退回。

| 找房进度状态 | 已联系 / 申请 | 收到回复 | Viewing | 正在推进 | 已确认住房 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 待处理 | 0 | 0 | 0 | 0 | 0 |
| 已表达意向 | 1 | 0 | 0 | 1 | 0 |
| 准备申请材料 | 1 | 0 | 0 | 1 | 0 |
| 已提交申请 | 1 | 0 | 0 | 1 | 0 |
| 已收到回复 | 1 | 1 | 0 | 1 | 0 |
| 已预约看房 | 1 | 1 | 1 | 1 | 0 |
| 已签约 | 1 | 1 | 1 | 0 | 1 |

已结束的房源仍可作为累计申请、回复和 Viewing 反馈，但不计入“正在推进”或“已确认住房”。

## 术语

- **Viewing**：已经获得看房邀请，或已经预约、完成看房。它对应“已预约看房”及之后的当前状态。
- **正在推进**：尚未结束、尚未签约，并且已经从“待处理”进入联系或申请流程的房源。它不是房东已经给出的 Offer。
- **已确认住房**：当前状态为“已签约”且没有被标记为结束。

## 影响策略的位置

`expatus/services/progress_summary.py` 先生成账户级摘要，`expatus/services/strategy_engine.py` 再使用它调整：

- 当前阶段说明和申请反馈诊断；
- 渠道状态、动作和优先级；
- 资格与材料复盘所占的建议时间；
- 本周三项行动；
- Plan B 的启动时机；
- 策略依据和解释文案。

前端 `static/js/my-housing-strategy.js` 只展示服务端结果。普通同步调用 `GET /api/strategies/current`，按最新房源状态重新计算完整策略，不消耗每日生成次数。
